# Share image and search metadata

## What it is

`public/og-image.png` (1200x630) is the picture LinkedIn, Slack, X and others show when someone shares a
link to the site. Every page uses it through `src/components/layout/SeoHead.astro`. The source is
`docs/assets/og-image.html`.

## Regenerating the image

Do this when the name, title, or tagline changes, or when the design tokens change.

1. Edit `docs/assets/og-image.html` (copy must follow `docs/content-guide.md`).
2. Save this as `render-og.mjs` in the repo root (don't commit it):

   ```js
   import { chromium } from '@playwright/test';
   import { resolve } from 'node:path';
   import { pathToFileURL } from 'node:url';

   const browser = await chromium.launch();
   const page = await browser.newPage({ viewport: { width: 1200, height: 630 } });
   await page.goto(pathToFileURL(resolve('docs/assets/og-image.html')).href);
   await page.evaluate(() => document.fonts.ready);
   await page.screenshot({ path: 'public/og-image.png' });
   await browser.close();
   ```

3. Run `node render-og.mjs`, delete the script, and look at the PNG before committing.
4. After the release, check a preview with a link debugger (for example LinkedIn's Post Inspector).
   Sites cache previews, so an old image can stick around for a few days.

## Metadata rules

- Canonical, `og:url`, and `og:image` always use the production URL, even on PR previews.
- PR previews, the 404 page, and `/contact/thanks/` are `noindex`. The 404 and thank-you pages also have
  no canonical or `og:url`: a canonical would contradict `noindex`, and on the 404 page it would name `/404/`,
  which doesn't exist.
- The sitemap (`/sitemap-index.xml`) is only built for production. It leaves out `/contact/thanks/` and
  the 404 page. `robots.txt` is generated by `src/pages/robots.txt.ts` and points at it.

## Known limitation: 404 on PR previews

GitHub Pages only serves the root `404.html`. A missing page under `/pr-preview/pr-<N>/` shows the
production 404 page, not the preview's. Test 404 changes locally with `pnpm build && pnpm preview`.
